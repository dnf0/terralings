    Specification: Terralings Onboarding Experience & Environment Diagnostics

    Date: 2026-08-27
    Status: Approved
    Author: Pair Programming Agent & Daniel Fisher
    Scope: internal/tour, internal/doctor, CLI commands (tour, doctor), First-run recommendation hooks, and docs/onboarding-guide.md.

    1. Executive Summary & Goals

    The goal of this specification is to create a seamless, guided onboarding experience for Terralings learners, matching the gold-standard architecture established in Kubelings.

    Key objectives: 1. Interactive CLI Tour Engine (terralings tour): A rich, multi-step interactive terminal walkthrough teaching learners how Terralings works, how exercises are structured, how to use watch/TUI modes, progressive hints, and editor LSP integration. 2. Environment Pre-flight Diagnostics (terralings doctor): A comprehensive health-check tool verifying local OpenTofu/Terraform installations, version compatibility, directory scaffold integrity, plugin cache permissions, and state persistence. 3. First-Run Guidance: Friendly, non-intrusive terminal callouts on terralings init and terralings root executions when a new user has 0 attempts recorded. 4. Headless & Editor Integration: --json and --non-interactive flags on tour and doctor to empower IDE extensions (VS Code, Neovim, Helix) and automated workflows. 5. Comprehensive Onboarding Documentation (docs/onboarding-guide.md): A complete beginner-to-advanced guide covering installation, doctor checks, tour steps, and editor workflows.

    2.1 The CLI Tour Engine (internal/tour)

    The tour engine provides a guided 5-step walkthrough rendered with Lip Gloss styling:

    Steps Breakdown:

    1. Step 1: Welcome & Core Philosophy
    2. Introduces Infrastructure-as-Code learning with OpenTofu & Terraform.
    3. Explains sandboxed isolated workspace evaluation without cloud credentials.
    4. Explains the pure deterministic validation model (Zero comment busywork).
    5. Step 2: Anatomy of an Exercise
    6. Explains exercises/ folder organization across 13 progressive chapters.
    7. Explains # TODO: task markers and deliberate educational bugs/stubs.
    8. Shows how exercises and reference solutions (solutions/) correspond.
    9. Step 3: Continuous Watch & Verification
    10. Teaches terralings watch workflow (Edit -> Save -> Green -> Next).
    11. Explains the interactive pass prompt ([Enter / n] Next | [p] Prev | [r] Rerun).
    12. Explains single-exercise runs via terralings run <exercise>.
    13. Step 4: Interactive TUI, Hints & Analytics
    14. Teaches the full-screen terminal dashboard: terralings tui / watch -i.
    15. Explains progressive hint extraction (terralings hint <exercise> [-i <idx>]).
    16. Explains learning statistics and progress tracking (terralings stats).
    17. Explains template reset (terralings reset <exercise>).
    18. Step 5: Editor Integration & Language Server (LSP)
    19. Teaches terralings lsp daemon usage for inline compiler diagnostics and markdown hover docs.
    20. Provides quick setup instructions for VS Code, Neovim, and Helix.

    Interactive Navigation Controls:

    • Enter or n / Right: Advance to next step.
    • p or Left: Go back to previous step.
    • 1 - 5: Direct jump to specified step.
    • r: Re-render current step.
    • q or Ctrl+C: Exit tour cleanly.

    2.2 Environment Diagnostics Doctor (internal/doctor)

    The diagnostic engine performs pre-flight verification of the user's environment to detect and resolve configuration issues before the user encounters runtime errors.

    Diagnostic Checks:

    1. Engine Binary Detection:
    2. Checks whether tofu or terraform is discoverable via PATH or --bin / TERRALINGS_BIN.
    3. Validates execution permissions and extracts version string (tofu version / terraform version).
    4. Status: PASS if found, FAIL if neither exists (with install instructions for Homebrew, curl, apt).
    5. Curriculum Scaffold Integrity:
    6. Verifies whether exercises/ exists in current workspace.
    7. Validates presence of 13 chapter folders and 56 exercise configurations.
    8. Status: PASS if complete, WARN if missing (recommending terralings init).
    9. Provider Plugin Cache:
    10. Verifies provider cache directory (runner.PluginCacheDir()).
    11. Checks directory creation and write permissions.
    12. Status: PASS if writable, WARN if fallback local cache is used.
    13. Progress State Persistence:
    14. Verifies .terralings/state.json store path.
    15. Validates JSON parseability and write permissions.
    16. Status: PASS if healthy, WARN if corrupt (noting automatic .bak recovery).
    17. Git Repository & Ignore Rules:
    18. Checks if workspace is a git repository (.git).
    19. Checks if .terralings/ is ignored in .gitignore.
    20. Status: PASS if properly ignored, WARN if missing from .gitignore.

    Data Structures (internal/doctor/doctor.go):

    package doctor

type CheckStatus string

const (
    StatusPass CheckStatus = "PASS"
    StatusWarn CheckStatus = "WARN"
    StatusFail CheckStatus = "FAIL"
)

type CheckResult struct {
    ID          string      `json:"id"`
    Name        string      `json:"name"`
    Status      CheckStatus `json:"status"`
    Message     string      `json:"message"`
    Resolution  string      `json:"resolution,omitempty"`
}

type DiagnosticReport struct {
    EngineDetected string        `json:"engine_detected"`
    EngineVersion  string        `json:"engine_version"`
    WorkspaceDir   string        `json:"workspace_dir"`
    Checks         []CheckResult `json:"checks"`
    Passed         bool          `json:"passed"`
    FailureCount   int           `json:"failure_count"`
    WarningCount   int           `json:"warning_count"`
}

func RunDiagnostics(workspaceDir string, binOverride string, stateOverride string) DiagnosticReport

    2.3 First-Run Guidance Hooks

    When a learner executes terralings or terralings init: - The CLI inspects the active state.Store. - If analytics.TotalAttempts == 0 && analytics.CompletedCount == 0: - A friendly Lip Gloss callout banner is displayed: 

    👋 Welcome to Terralings! New here?
   Run `terralings tour` for a 2-minute interactive guided walkthrough.
   Run `terralings doctor` to verify your OpenTofu/Terraform setup.

    2.4 Comprehensive Onboarding Guide (docs/onboarding-guide.md)

    Authored at docs/onboarding-guide.md, containing: 1. Quickstart Checklist: From zero to first solved exercise. 2. Environment Diagnostics: Troubleshooting binary detection with terralings doctor. 3. CLI Guided Tour: Step-by-step summary of the 5 tour modules. 4. Learning Modalities: When to use standard watch mode (terralings watch) vs full TUI dashboard (terralings tui). 5. Editor Setup Walkthrough: Full configurations for VS Code, Neovim (nvim-lspconfig), and Helix (languages.toml). 6. Curriculum Roadmap: Overview of all 13 chapters and key competencies.

    3. Testing Strategy

    1. test/tour_test.go:
    2. Verify all 5 tour steps are present with complete metadata.
    3. Verify interactive navigation (n, p, direct numbers 1-5, q).
    4. Verify --non-interactive mode prints all steps cleanly without blocking on stdin.
    5. Verify --step <n> renders the exact requested step.
    6. Verify --json outputs valid JSON containing all step objects.
    7. test/doctor_test.go:
    8. Verify detection of OpenTofu and Terraform engines.
    9. Verify handling when binary is missing (returns StatusFail with installation instructions).
    10. Verify exercises directory check with complete vs partial scaffold.
    11. Verify state store permissions and JSON diagnostics output.
    12. test/cli_onboarding_test.go:
    13. End-to-end CLI integration testing of terralings tour and terralings doctor.
    14. Test first-run welcome hook output on clean state.
